# BadOptimizations → Starling 26.3: feature-by-feature scope

This matrix audits **concepts**, not Java binaries. Original source: Thosea's [BadOptimizations at `5fa3416`](https://github.com/imthosea/BadOptimizations/tree/5fa3416f6148eaa4045399cf7fa24a5427cc2991) (`oldsrc/26.3`, MIT). Target source: Starling [`09fa16c`](https://github.com/starling-client/starling/tree/09fa16c167c4b2f8eb23fddd0faa808d56d0a2f2). A candidate does **not** imply a bottleneck exists on Android.

| Technique in original 26.3 source | Starling status | Next action |
| --- | --- | --- |
| Avoid redundant lightmap calculation (`MixinLightmapExtractor`) | **Prototype implemented.** Starling already avoids identical GPU uploads; the native patch skips the preceding 256-pixel CPU calculation when the cache key and pixels match. Combined Linux and ARM64 app Cargo checks passed. | Build a final ARM64 library, verify gameplay/visual parity and record A/B timings. |
| Debug renderer early exit (`MixinDebugRenderer`) | **Already guarded in native Rust.** `game/debug_renderers.rs` returns immediately in `debug_renderer_gizmos` when the collision visualization is off, and in `debug_renderer_geometry` when all relevant visualization flags are off. | No duplicated injection; re-evaluate only with evidence of idle cost. |
| Particle extraction early exit (`MixinParticleManager`) | **Native source port implemented.** HEAD of `ParticleEngine::render` returns early if `is_empty()` is true, avoiding per-call quaternion and light cache setup. | Combined source injection and ARM64 Cargo check passed; gameplay parity/profile pending. |
| Toast render early exit (`MixinToastComponent`) | **No corresponding general toast-render loop.** `game/narrator.rs` `draw_toast` exits at `toast.as_mut()?` when no toast is active; other toast paths are event/state based. | No Java-style empty-queue hook to copy. Preserve title-screen alerts and narrator behavior. |
| Skip tutorial tick outside demo (`MixinTutorial`) | **Incompatible to skip wholesale.** Starling's `game/tutorial.rs` includes real survival tutorial steps outside demo mode; `Tutorial::tick` advances them. | Skipping non-demo ticks would alter gameplay/tutorial behavior, so exclude. |
| Avoid redundant camera FOV calculations (`MixinCamera`) | **Native source port implemented.** HEAD of `field_of_view_modifier` skips extra calculations only for `effect_scale == 0`, returning 0.1 for first-person spyglass or 1.0 otherwise; nonzero scale runs original. | Combined source injection and ARM64 Cargo check passed; gameplay parity with mods/hooks pending. |
| Entity-renderer lookup caching (`MixinEntityRendererDispatcher`, `MixinEntityType`, `MixinEntity`) | **Not equivalent to native entity dispatch.** Rust entities are represented by typed lists with static dispatch (see `game/entity.rs`), not Java `EntityRendererDispatcher` map lookups per entity. | Avoid injecting a redundant map/cache. |
| Block-entity renderer lookup caching (`MixinBlockEntityRenderDispatcher`, `MixinBlockEntityType`) | **Native model/geometry cache exists.** `block_entity_render.rs` has `StaticGeometry`, `CacheOptions`, cache invalidation and compiled models; Java `BlockEntityType` lookup caching is not a direct counterpart. | No direct port without demonstrating an unoptimized equivalent lookup. |
| Other `Config.java` toggles (sky angle, entity flags, etc.) | **Configuration-only flags; no matching active 26.3 mixins found** in the pinned original source for sky-angle caching or entity-flag caching. | Do not claim a port of a feature that has no 26.3 implementation. |
| Legacy sky-colour caching | **Excluded.** The original project's changelog removed it after 1.21.10 with data-driven sky colours. | No 26.3 port without new evidence. |

## Acceptance rules

For each technique: verify the exact upstream implementation and license; find and profile the equivalent Starling path; reproduce with tests before changing logic; apply mixins and compile with the pinned source; validate ARM64 gameplay and visual parity; then publish measurable CPU/frame-time improvement or a documented negative result.

**Lightmap target:** `crates/horizon-client-render/src/gfx.rs`, `Renderer::update_lightmap` in pinned Starling. The existing GPU-upload guard uses `lightmap_uploaded` and `lightmap_pixels`. The current thread-local prototype uses the 16 input values read by this method, the last 1024 output bytes, renderer identity and upload flag. Hook compatibility, resource-reload behavior and GPU recovery still need in-game tests.
